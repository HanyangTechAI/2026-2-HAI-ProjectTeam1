### 3.1 Proposed: 필수 기억 보존과 행동 인자 사용의 간극

2K 이상에서는 최종 Context의 정답·필수 제약 누락이 없었다. 실패 18회는 모두 `seed43_approval_014_pending`이라는 기본 과제 하나를 3개 Horizon × 3개 Budget × 두 반복으로 관측한 것이다. 독립 실패 과제 18개로 해석하지 않는다.

이 사례는 승인 제약을 지키고 본문에도 정답 최신 파일을 썼지만 request_approval의 구조화된 attachment 인자가 없었다. 응답 스키마는 이를 조건부 필수로 강제하지 않고 승인 요청 Tool도 생략을 허용한다. 반면 이 과제의 사전 평가 계약은 attachment로 정답 파일을 사용해야 한다. 따라서 메모리 선택 실패로 단정하기보다 도구 인자 사용 및 인터페이스 계약의 한계로 분류한다.

기존 기준대로 실패를 유지했다. 본문에 파일 이름이 있다는 이유로 평가를 바꾸지 않았다. 최종 Context 정확성은 true지만 행동 State 정확성은 false일 수 있다. 원문 모델 JSON이 없는 Main run에서는 누락과 빈 값 제거의 세부 원인까지 확정하지 않는다. Context 구성 방식의 간접 영향도 별도 실험 없이 배제할 수 없다.

- 비용 불완전은 H100·2K에만 있으며 4K·8K의 관측 비용 비교에는 해당 누락이 없다. 그래도 실제 청구액과는 구분한다.

## 7. 출력과 입력 Budget 진단

- 실제 LLM 실행 3,600회. 생성 API 시도 7,453회 중 응답 객체 7,450개를 받았고, 그 응답의 finish_reason은 전부 STOP이다.
- 3개의 응답 없는 재시도 시도는 위 비용 불완전성과 함께 기록됐다. 따라서 API 시도가 모두 오류 없이 성공했다고 표현하면 안 된다.
- MAX_TOKENS·응답 해석 실패·실제 입력 예산 초과·CountTokens 실효 예산 초과·live prompt audit 누락은 모두 0건이다. 최대 단일 응답 출력은 thinking 포함 1,288 token이다.
- 출력 상한 2048은 이번 12셀에서는 충분했다. 입력 8K 조건이 실제 8K 경계까지 꽉 찬 요청을 검증했다는 뜻은 아니다.
- 제약 위반은 전체 14회이며 모두 2K Sliding에서 발생했다. 대부분의 실행이 적용 제약이 없거나 다른 조건이므로 전체 평균만으로 이 집중된 문제를 숨기지 않는다. Proposed의 1K 위반 0건은 호출을 하지 않은 결과다.
